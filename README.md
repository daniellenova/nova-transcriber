# Nova Transcriber

Проект находится в разработке.

## Назначение

Nova Transcriber — локальный сервис автоматической транскрибации аудио- и видеозаписей с сохранением результатов и истории.

## Ключевая идея

Простой, автономный и расширяемый сервис с логическим разделением способов взаимодействия, распознавания речи, бизнес-логики и хранилища. Модульность без преждевременной микросервисной архитектуры.

## Технологический стек MVP

- Python и uv.
- faster-whisper и Whisper Large-v3.
- CPU, INT8.
- Docker Compose.
- PostgreSQL.
- Telegram, aiogram и локальный Telegram Bot API.

## Архитектурные принципы

- Telegram — один из возможных интерфейсов; Core от него не зависит.
- ASR — отдельный заменяемый модуль; Core не зависит от конкретного движка.
- PostgreSQL хранит метаданные и полные тексты транскрибаций.
- Независимые Telegram Adapter, Core API и Whisper Worker; очередь в PostgreSQL.
- Перенос на другой компьютер через Docker Compose.

## Функциональность MVP

1. Получение аудио или видео через Telegram.
2. Распознавание русской речи.
3. Сохранение транскрибации и метаданных в PostgreSQL.
4. Возврат полного текста в TXT.
5. Получение предыдущих результатов через `/history`.
6. Доступ только разрешённому Telegram-пользователю.

## Направление развития

Веб-интерфейс, другие ASR-модели, удалённые вычислители и дополнительные способы обработки текста — возможные направления развития, а не функции текущего MVP.

## Локальный CLI

Положите аудиофайл в `./data` и из корня проекта выполните:

```sh
uv run --extra worker nova-transcriber "data/Запись.m4a"
```

TXT появится рядом с исходным файлом. Для локального CLI нужны Python и модель в `./models/large-v3`.

Зависимости разделены по extras: `postgres` для Core API, `telegram` для Adapter, `worker` для ASR и CLI. Образ Worker устанавливает `worker` и `postgres`; образы Core и Adapter не устанавливают ML-библиотеки. На Windows общая зависимость `tzdata` обеспечивает работу часовых поясов.

## Telegram

`MAX_FILE_SIZE_MB` в `.env` задаёт максимальный размер входящего файла: по умолчанию 100 МиБ (104 857 600 байт). Допустимо положительное конечное число, включая дробное; неверное значение останавливает запуск с ошибкой конфигурации. После изменения пересоздайте контейнер: `docker compose up -d --build telegram-adapter core-api`.

Размер из метаданных сообщения проверяется до `get_file`, фактический размер локального файла — до Core, декодирования и Whisper. При неизвестных или заниженных метаданных локальный Bot API может сначала получить файл; приложение проверяет его через `stat()`, не читая целиком в память и не удаляя из общего тома. Самостоятельного скачивания и управления загрузкой внутри Bot API в приложении нет.

Скопируйте `.env.example` в `.env`, задайте пароль PostgreSQL, `TELEGRAM_BOT_TOKEN` от @BotFather, свой числовой `TELEGRAM_ALLOWED_USER_ID`, а также `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` с [my.telegram.org](https://my.telegram.org/apps).

Если бот уже работал через облачный Bot API, остановите прежний процесс и один раз вызовите метод `logOut` на облачном сервере перед переходом на локальный. При активном webhook сначала удалите его методом `deleteWebhook`. См. [инструкцию Telegram](https://core.telegram.org/bots/api#using-a-local-bot-api-server).

Из корня проекта выполните:

```sh
docker compose up -d --build
```

Команда запускает `postgres`, `telegram-bot-api`, `core-api`, `telegram-adapter` и `whisper-worker`. Задайте также `CORE_API_TOKEN` (случайный секрет от 32 символов). Модель должна находиться в `./models/large-v3`. Telegram Adapter создаёт задачи и получает результаты через Core API; Worker забирает задачи из PostgreSQL и выполняет распознавание. Команды `/start` и `/history` доступны разрешённому пользователю. API опубликован на `127.0.0.1:8000`, PostgreSQL — на `127.0.0.1:5433`. Исходные файлы читаются из общего volume без копирования.

Adapter опрашивает уведомления раз в пять секунд. Его перезапуск не останавливает Worker. Прерванная задача Worker получает `failed` после освобождения блокировки PostgreSQL и следующего опроса очереди; автоматически повторно она не запускается. При сетевом обрыве после фактической отправки TXT, но до подтверждения доставки возможна повторная отправка.

Перезапуск отдельного компонента: `docker compose restart telegram-adapter` (или `core-api`, `whisper-worker`). Несколько Worker: `docker compose up -d --scale whisper-worker=2`. Telegram Adapter остаётся в одном экземпляре.
